# Практика 8 · Читальня

Читатель добавляет «Солярис» Станислава Лема, видит книгу в списке и обновляет страницу. Книга остаётся в библиотеке. Команда CLI видит ту же запись в SQLite.

## От макета к реализации

[Первый вариант](prototype-draft.html) и [уточнённый интерактивный прототип](prototype.html) открываются локально в браузере. Для просмотра на GitHub скачайте HTML. Внизу макета выберите одно из пяти состояний. Введите своё название и нажмите «Добавить книгу», чтобы пройти переход от ввода через сохранение к результату.

Для прототипа, интерфейса и тестов использовали Codex.

| Этап | Пример запроса к AI | Что проверено и доработано |
|---|---|---|

В уточнённом варианте результат берётся из полей, добавлены счётчик и оформление списка из готового интерфейса. Произвольное название проверяется браузерным тестом. |
| Интерфейс | Переиспользуй MUI TextField, Button, Card, Alert и CircularProgress. Подключи список и форму к SQLite через API. | Обработчик держит синхронный флаг до завершения POST. ## Демонстрация

1. Запустите API и Vite по инструкции в [README](../README.md). Для демонстрации с пустой библиотекой выберите новый путь базы через `--db`.
2. Нажмите Tab, введите «Солярис», перейдите к автору и введите «Станислав Лем». Следующее нажатие Tab переводит фокус на кнопку, Enter сохраняет запись.
3. Обновите страницу. Сверьте запись через CLI с тем же путём базы. Попробуйте оставить название пустым или ввести пробелы.
4. Для воспроизводимой задержки и ошибки запустите мобильный тест Playwright. Он задерживает ответ и возвращает HTTP 503. Основной браузерный сценарий работает с настоящей SQLite во временной папке.

## Описание тестов

Для практики 8 добавлены пять компонентных и три браузерных теста. Их запускает `npm test`. Семь существующих тестов CLI запускаются отдельно и проверяют поведение консольного приложения после подключения веб-интерфейса.

### Компонентные тесты формы и списка

Vitest и React Testing Library отображают приложение и воспроизводят действия пользователя. Тесты подменяют `fetch`, поэтому могут задать последовательность ответов и удерживать запрос незавершённым. Запуск этой группы — `npm run test:unit`. [Исходный код](../src/App.test.tsx)

| Сценарий | Действия и ожидаемый результат |
|---|---|
| Загрузка и восстановление после сбоя | При открытии появляется «Загружаем». Первый запрос получает HTTP 503. Пользователь нажимает «Повторить», следующий запрос возвращает пустой массив, и появляется «Пока нет книг». |
| Пустое название | Пользователь сразу отправляет форму. Появляется «Введите название книги.», фокус возвращается в поле. Единственный вызов `fetch` за весь сценарий — первоначальная загрузка списка. |
| Название из трёх пробелов | Та же проверка выполняется отдельно с введёнными пробелами. Форма показывает ошибку, возвращает фокус в поле и блокирует отправку. |
| Повторная попытка сохранения | Пользователь вводит «Солярис». После ответа 503 он видит сообщение об ошибке и своё название в поле. При повторной отправке сервер отвечает 201, «Солярис» появляется в списке, поле очищается. |
| Защита от дублей | Тест задерживает ответ и воспроизводит двойной клик, два нажатия Enter и отдельное событие `submit`. Пока кнопка «Сохраняем…» заблокирована, уходит ровно один `POST`. В его теле название очищено от крайних пробелов, автор — пустая строка. После получения ответа появляется «Книга добавлена.». |

### Браузерные тесты

Playwright запускает три сценария в Chromium. Команда для этой группы — `npm run test:e2e`. [Исходный код](../e2e/library.spec.ts)

1. **Сохранение с клавиатуры через настоящий API.** Тест поднимает Python-сервер с новой временной базой SQLite. В пустой библиотеке пользователь клавишей Tab переходит к названию, вводит «Солярис» и автора «Станислав Лем», доходит до кнопки и нажимает Enter. Тест проверяет фокус, появление книги и подтверждение сохранения. После обновления страницы он находит автора, сверяет ID, название, автора и статус чтения в ответе `GET /api/books`, затем находит книгу через CLI. Проверяется и обратный путь: «Пикник на обочине», добавленный через CLI в ту же базу, появляется в браузере после обновления.
2. **Мобильная форма при задержке и ошибке.** В окне 360 × 800 пикселей Playwright перехватывает запросы к API. Загрузка возвращает пустой список, а запрос сохранения ожидает, пока тест проверит блокировку кнопки. Затем приходит HTTP 503. Тест проверяет предложение повторить попытку, сохранение имени автора в поле и отсутствие горизонтальной прокрутки.
3. **Интерактивный прототип.** Тест открывает HTML-макет, выбирает состояние «Ошибка» и проверяет текст сообщения. Затем вводит «Дюна», отправляет форму и проверяет блокировку кнопки во время сохранения. В списке должна появиться именно «Дюна». Так тест обнаружит возврат ошибки первого макета, который всегда подставлял «Солярис».

### Тесты консольного приложения

Каждый тест Python использует отдельный временный каталог для базы SQLite и вызывает точку входа CLI с аргументами команды. Запуск — `python3 -m unittest discover -s tests -v`. [Исходный код](../tests/test_reading_list.py)

| Проверка | Ожидаемый результат |
|---|---|
| `list` в пустой библиотеке | Вывод «Список чтения пуст.», код завершения 0. |
| `add`, затем отдельный вызов `list` | Сохранённая книга отображается с ID, автором и статусом «к прочтению». |
| `list --unread` для двух книг, первая уже прочитана | В списке остаётся только вторая книга. |
| `list --unread`, когда прочитаны все книги | Вывод «Нет непрочитанных книг.», код завершения 0. |
| `read 2` для библиотеки из двух книг | У второй книги появляется статус «прочитано», у первой остаётся «к прочтению». |
| `read 99` для отсутствующего ID | Сообщение «Книга #99 не найдена.» направляется в поток ошибок, код завершения 1. |
| `add` с названием из пробелов | CLI отклоняет аргумент с кодом 2 до создания файла базы. |
